# Совместимость с инсталлером AmneziaWG

[English version](compat.en.md)

awgram — надстройка над `manage_amneziawg.sh` из
[bivlked/amneziawg-installer](https://github.com/bivlked/amneziawg-installer)
и напрямую зависит от его `--json`-интерфейса. Здесь — что именно
используется и как каждая версия инсталлера повлияла (или не повлияла)
на бота.

## Кратко

| | Версия |
|---|---|
| Поддерживаемая (сверен `--json`-контракт) | [v6.2.2](https://github.com/bivlked/amneziawg-installer/releases/tag/v6.2.2) |
| Минимальная | [v5.21.0](https://github.com/bivlked/amneziawg-installer/releases/tag/v5.21.0) |

v5.20.x и старше не поддерживаются: бот использует расширенный
`--json`-интерфейс команд управления, появившийся в v5.21.0.

Используемые подкоманды — все с `--json`: `add`, `remove`, `list`, `stats`,
`regen`, `modify`, `backup`, `restore`, `check`, `restart`, `repair-module`.

## Необязательный `add --allowed-ips`

Флаг из [Issue #253](https://github.com/bivlked/amneziawg-installer/issues/253)
(в инсталлере с v5.32.0) позволяет задать индивидуальные маршруты клиента одной командой вместе с
созданием. Бот определяет наличие флага по справке самого скрипта
(`--help`, ничего не меняет), а не по номеру версии: релиз с флагом заранее
не известен, а на полуобновлённом сервере номер и реальность расходятся.

- Флаг есть — клиент создаётся сразу с нужными маршрутами, промежуточного
  состояния «клиент есть, маршрутов нет» не бывает.
- Флага нет — прежний путь `add`, затем `modify` до выдачи файлов;
  минимальная версия не меняется.
- У массовой генерации отката нет: `modify` пришлось бы звать на каждого
  клиента, поэтому без флага шаг маршрутов там не показывается.

## Адрес сервера вне AllowedIPs клиента

С v6.0.0 `add` и `regen` вырезают из AllowedIPs клиента IPv4-адрес из его
`Endpoint`: маршрут `/n`, накрывающий адрес, становится `32−n` маршрутами
(`0.0.0.0/0` не трогается, для имени хоста и IPv6 дыры нет). Это исправление
для Linux-клиентов на `awg-quick`: он ставит правило маршрутизации только
для `0.0.0.0/0`, и список, накрывающий адрес сервера, заворачивал в туннель
пакеты к самому серверу. Приложения для Windows, Android и iOS ставят
маршрут до сервера сами, им дыра не мешает. Выключателя у выреза нет.

Для бота это значит:

- в ответе `add --allowed-ips` поле `allowed_ips` шире переданного списка:
  в режиме «исключать из VPN» публичный адрес сервера всегда внутри;
- экран маршрутов сверяет список клиента с пресетами, терпя дыру у IPv4 из
  `Endpoint` того же `.conf`: такой клиент показывается своим пресетом, а не
  как «задано вручную»; дыра у другого адреса остаётся чужой настройкой;
- `modify AllowedIPs` инсталлер пишет как есть (только предупреждает),
  поэтому при «Применить» на экране маршрутов бот вырезает адрес сервера
  сам, по тому же правилу: конфиг после правки через бота совпадает с тем,
  что выдал бы `add`/`regen`, и дыра не исчезает до следующего `regen`.
  Бот делает это на любой версии инсталлера: на старых дыра безвредна
  (приложения ставят маршрут до сервера сами), а их `regen` считает такой
  список индивидуальным и не трогает. Если из IPv4-маршрутов остался бы
  один адрес сервера, бот список не меняет — `modify` запишет его как
  задан и предупредит;
- список, где из IPv4-маршрутов остаётся только адрес сервера, `add`/`regen`
  отвергают до записи конфига — прежним `status:"error"`; пресеты бота такой
  список не собирают.

## Как проверяется новая версия инсталлера

При выходе нового релиза инсталлера сверяется diff `manage_amneziawg.sh`
и `awg_common.sh` (логика `add`/`regen` и маршрутов живёт в библиотеке, и
обновляются они парой): конверты `--json` используемых подкоманд, коды
выхода, новые поля и предупреждения. Если контракт не изменился —
обновляется только эта таблица и бейдж в README; если изменился — правка
попадает в CHANGELOG как совместимость с конкретной версией.
