# Совместимость с инсталлером AmneziaWG

[English version](compat.en.md)

awgram — надстройка над `manage_amneziawg.sh` из
[bivlked/amneziawg-installer](https://github.com/bivlked/amneziawg-installer)
и напрямую зависит от его `--json`-интерфейса. Здесь — что именно
используется и как каждая версия инсталлера повлияла (или не повлияла)
на бота.

## Кратко

| | Версия |
|---|---|
| Поддерживаемая (сверен `--json`-контракт) | [v5.31.0](https://github.com/bivlked/amneziawg-installer/releases/tag/v5.31.0) |
| Минимальная | [v5.21.0](https://github.com/bivlked/amneziawg-installer/releases/tag/v5.21.0) |

v5.20.x и старше не поддерживаются: бот использует расширенный
`--json`-интерфейс команд управления, появившийся в v5.21.0.

Используемые подкоманды — все с `--json`: `add`, `remove`, `list`, `stats`,
`regen`, `modify`, `backup`, `restore`, `check`, `restart`, `repair-module`.

## Необязательный `add --allowed-ips`

Флаг из [Issue #253](https://github.com/bivlked/amneziawg-installer/issues/253)
позволяет задать индивидуальные маршруты клиента одной командой вместе с
созданием. Бот определяет наличие флага по справке самого скрипта
(`--help`, ничего не меняет), а не по номеру версии: релиз с флагом заранее
не известен, а на полуобновлённом сервере номер и реальность расходятся.

- Флаг есть — клиент создаётся сразу с нужными маршрутами, промежуточного
  состояния «клиент есть, маршрутов нет» не бывает.
- Флага нет — прежний путь `add`, затем `modify` до выдачи файлов;
  минимальная версия не меняется.
- У массовой генерации отката нет: `modify` пришлось бы звать на каждого
  клиента, поэтому без флага шаг маршрутов там не показывается.

## История по версиям инсталлера

Ни одна из версий v5.21.1–v5.31.0 JSON-контракт не ломала. Все новые
сообщения уходят в stderr, конверты `--json` в stdout не менялись.

| Версия | Что изменилось | Влияние на бота |
|---|---|---|
| v5.21.1, v5.21.2 | Багфиксы валидации | Нет |
| v5.22.0 | `regen`/`check` предупреждают о рассинхроне `awgsetup_cfg.init` | Нет (stderr) |
| v5.23.0 | Только установщик: модуль ядра на старых ядрах | Нет |
| v5.24.0 | Аддитивное поле `module.version` в `check --json` | Нет |
| v5.25.0 | Только новые предупреждения | Нет (stderr) |
| v5.26.0 | Каскадный скрипт маршрутизации, диагностический отчёт | Нет |
| v5.27.0 | Только установщик: согласие на удаление пакетов | Нет |
| v5.27.1 | `modify`/`regen` нормализуют списки `AllowedIPs`/`DNS` к виду «a, b, c», `regen` больше не схлопывает их | Нет: `value` в ответе `modify` остаётся присланным, бот и так шлёт списки в каноническом виде |
| v5.28.0, v5.29.0 | Только установщик (защита загрузочных пакетов, маскирование ключей в отчёте), подписи релизов, документация | Нет: в `manage_amneziawg.sh` сменился лишь номер версии |
| v5.30.0 | Все обращения к интерфейсу ограничены таймаутом; непрочитанное состояние не выдаётся за измеренное | `list --json` при неудачном чтении оставляет клиентам `no_data` — бот красит их жёлтым; `check --json` может отдать пустой `interface.addresses` — пресет подсети VPN скрывается, массовая генерация сообщает о недоступной ёмкости |
| v5.31.0 | Полный туннель определяется покрытием маршрутов; дефолтный режим «Amnezia» получает `::/0`; `modify` предупреждает о полном туннеле без `::/0` | Нет: пресет «весь трафик» шлёт `0.0.0.0/0, ::/0`, предупреждение не срабатывает |

## Как проверяется новая версия инсталлера

При выходе нового релиза инсталлера сверяется diff `manage_amneziawg.sh`:
конверты `--json` используемых подкоманд, коды выхода, новые поля и
предупреждения. Если контракт не изменился — обновляется только эта
таблица и бейдж в README; если изменился — правка попадает в CHANGELOG
как совместимость с конкретной версией.
