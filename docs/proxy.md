# Прокси до Telegram Bot API

[English version](proxy.en.md)

Бот ходит только в `api.telegram.org` (обычный HTTPS, long polling). Если с
сервера этот адрес недоступен напрямую, есть два пути: прокси в конфиге бота
или маршрутизация Telegram-подсетей через уже существующий туннель.

## Вариант 1: `telegram_proxies` в конфиге

```toml
# /etc/awgram/config.toml
telegram_proxies = [
  "socks5h://user:pass@10.8.0.1:1080",
  "http://10.8.0.2:3128",
]
```

- **Схемы**: `socks5://`, `socks5h://`, `http://`, `https://`.
  Логин и пароль указываются прямо в URL; спецсимволы в них нужно
  percent-encode (например, `p@ss` → `p%40ss`). Другие схемы (в том числе
  MTProto-прокси) не поддерживаются: Bot API — обычный HTTPS, MTProto к нему
  неприменим.
- **Рекомендуется `socks5h://`**: DNS-имя `api.telegram.org` резолвится на
  стороне прокси. С `socks5://` резолв происходит локально — в условиях
  подмены DNS-ответов это слабое звено.
- **Список приоритетный, не round-robin**: при старте бот проверяет прокси
  по порядку лёгким запросом `getMe` (таймаут 10 с) и работает через первый
  ответивший. Если не ответил ни один — бот завершается с ошибкой, systemd
  перезапускает его через 5 с, и проверка повторяется.
- **Фейловер в рантайме**: раз в 60 с бот проверяет соединение; после трёх
  провалов подряд процесс завершается, systemd поднимает его заново — и
  выбор снова начинается с первого прокси в списке. В худшем случае от
  смерти прокси до перезапуска проходит ≈3×(60 + 10) ≈ 3,5 минуты. Пока
  прокси мёртв, бот молчит; сам VPN при этом работает как обычно.
- **Логи**: креды из URL прокси в логи и Debug-вывод не попадают —
  печатается только `схема://***@хост:порт`.

## Вариант 2: маршрутизация без прокси

Если сервер уже гоняет трафик через зарубежную машину (например, клиенты
роутятся через туннель), прокси не нужен: достаточно направить локальный
трафик до адресов Telegram в тот же туннель — политикой маршрутизации или
правилами firewall.

- Адресное пространство Telegram стабильно; его легко получить по
  **ASN62041** (например, из BGP-данных: `whois -h whois.radb.net -- '-i origin AS62041'`)
  и персистить любым удобным способом.
- Не забудьте **IPv6**: если у сервера есть IPv6-адрес, а маршрут добавлен
  только для IPv4-подсетей, трафик уйдёт напрямую по AAAA-записи.
- При падении туннеля бот замолчит так же, как при мёртвом прокси, — но
  автоматического фейловера здесь нет: восстановление туннеля на вашей
  стороне.
